# 子用户个人工作区自动开通

启用后，新增子用户会自动获得个人目录和 DSH 工作区；插件启动时为现有子用户补建。目录使用数据库固定用户 ID，例如 `D:\dshWorkspace\user\u_12`。用户名变化不会搬动目录。

## 部署配置

在 `MCP_DB_PATH` 所在目录创建 `personal-workspaces.json`。文件不含凭据，示例：

```json
{
  "enabled": true,
  "root": "D:/dshWorkspace/user",
  "readOnlyFolders": ["D:/dshWorkspace/source"]
}
```

6.4 部署路径是 `C:\SmartAll\AI\data\passwords\personal-workspaces.json`。未配置文件或设置 `enabled: false` 时，保留上游行为。修改配置后需重新加载 DSH 服务。

个人目录根和共享目录必须分开，不能互相包含。目录存在但非空且无法确认归属时，开通失败，不覆盖或接管。拒绝个人目录的符号链接与 junction。

## 自动行为

1. 创建 `root\u_<用户 ID>`，写入归属标记。
2. Windows 上先核对目录归属标记，再将个人目录的所有者设为 DSH 宿主运行账户，并为该账户补齐沙盒准备所需的完整控制权限。变更前保存权限快照，重复调用不重写已满足条件的权限。随后在个人目录缺少 `AGENTS.md` 时生成入口说明，引用共享规则和源码分析 Skill；已有入口文件保留。
3. 使用 DSH 工作区服务登记目录，写入子用户归属。
4. 首次开通时，只把个人目录加入读取白名单；共享目录不自动授权，由主用户按人员需要分配。无范围限制的旧账号收敛到个人目录；其他已有明确白名单保留。
5. 首次开通时明确设置 `workspace-write`。管理员已明确设置的 `read-only` 保留；配额、封禁、SSH、下载和会话授权不重置。
6. 浏览器标签页首次获取个人工作区后自动进入该工作区。后续刷新保留主动选择；旧会话的工作目录不迁移。

重复补建不新增重复工作区，不覆盖文档，不恢复管理员已撤销的目录权限。删除账号保留个人目录和文件。

新增账号后登记工作区失败时，接口返回 `PERSONAL_WORKSPACE_FAILED`，并提示账号已经创建，不要重复创建。失败账号保留默认拒绝目录权限；重启后补建，或由主用户使用补建接口重试。

## 主用户补建接口

`POST /api/dsh-passwords/personal-workspaces/repair` 使用现有主用户登录态和同源校验。空 JSON 对象补建全部子用户；指定 `{"userId": 12}` 只处理对应账号。每项返回成功状态、工作区路径或失败原因。子用户不能调用此接口。

## 共享源码写入限制

`readOnlyFolders` 只声明需要保护的共享目录，不表达新用户默认授权。启用配置后，密码门为子用户确认会话沙箱时，将工作目录位于 `readOnlyFolders` 下的会话降为 `read-only`。个人目录会话使用用户已授予的沙箱档位。该限制覆盖现有 HTTP/Remote 请求共同使用的内部沙箱确认入口，不修改主用户的维护权限。

个人目录会话中的原生文件写入仍由 `workspace-write` 检查目标路径；Windows 命令工具仍使用原有受限令牌。目录准备只为 DSH 宿主账户补齐个人目录的 Windows 所有者和权限，不改变子用户的源码授权或沙盒档位，不提供独立 Windows 账号或所有外部插件的文件系统隔离。共享源码的操作系统只读保护可以另行实施。

Windows 权限快照位于密码门数据库旁的 `workspace-acl-backups`，准备程序使用服务 PATH 中的 PowerShell 7（`pwsh.exe`；6.4 已配置）。准备失败时尝试恢复本次修改并返回 `PERSONAL_WORKSPACE_FAILED`；如错误提示回退需要复核，应先核对快照和当前权限。现有账号在启动补建或主用户调用补建接口时执行相同检查，无需重新创建账号。部署前应确认个人目录根允许 DSH 宿主账户为新目录设置所有者和权限；不向 DSH 子用户开放全盘权限。

## 验收

- 新建子用户后无需手工添加目录或登记工作区，登录后进入个人工作区。
- 现有子用户获得固定 ID 的个人工作区，历史会话及文件保留。
- 新用户默认只获得个人目录。管理员明确分配共享目录后，再验收源码与规则的读取；报告保存到个人目录。
- 子用户以共享源码为工作目录发起分析时，实际沙箱为只读。
- 重复补建、改名不产生重复目录或工作区。
- 目录冲突或登记失败可观察；修复原因后可以重试。
- Windows 上用原有受限令牌执行目录查看、个人目录临时文件写入与删除，并确认写入其他工作区仍被拒绝。

## 维护与回退

这是当前部署的本地扩展。上游包升级可能覆盖扩展，升级前需重新合并并执行上述验收。回退时恢复发布前备份的安装文件并移除或禁用配置；保留已经生成的用户目录和工作区记录，不批量删除账号或文件。回退不会自动撤销已授予的目录权限，应由主用户按实际需要调整。
